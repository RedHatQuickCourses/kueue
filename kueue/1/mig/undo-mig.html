Undo MIG

To remove MIG and restore all 4 GPUs as whole devices, follow these steps in order.

References

  • Fake GPU Operator

Lab: Remove MIG and Restore Whole GPUs

1. Remove the MIG annotation and labels

Remove the MIG configuration applied by 6a-mig-node-config.yaml:

$ oc annotate node $WORKER_NODE1 run.ai/mig.config-
node/worker-cluster-vnnbf-1 annotated

$ oc label node $WORKER_NODE1 \
  node-role.kubernetes.io/runai-dynamic-mig- \
  node-role.kubernetes.io/runai-mig-enabled-
node/worker-cluster-vnnbf-1 unlabeled

2. Restore the topology ConfigMap

Restore the topology ConfigMap to 4 whole GPUs (remove otherDevices, add GPU 0 back). The simplest approach: delete the ConfigMap and restart the status-updater to regenerate it.

$ oc delete configmap topology-$WORKER_NODE1 -n gpu-operator
configmap "topology-worker-cluster-vnnbf-1" deleted from gpu-operator namespace

$ oc delete pod -n gpu-operator -l app=status-updater
pod "status-updater-549984dff-xhcpc" deleted from gpu-operator namespace

3. Restart the device-plugin

Wait for the status-updater to recreate the ConfigMap, then restart the device-plugin:

$ sleep 15;oc delete pod -n gpu-operator $(oc get pods -n gpu-operator -l app=device-plugin \
  -o jsonpath="{.items[?(@.spec.nodeName==\"$WORKER_NODE1\")].metadata.name}")
pod "device-plugin-t7vbh" deleted from gpu-operator namespace

4. Verify 4 whole GPUs are back

$ sleep 15;oc get node $WORKER_NODE1 -o jsonpath='{.status.allocatable}' | python3 -m json.tool | grep -E 'gpu|mig'
    "nvidia.com/gpu": "4",
    "nvidia.com/mig-1g.5gb": "0",
    "nvidia.com/mig-2g.10gb": "0",
    "nvidia.com/mig-3g.20gb": "0",

The MIG resource types showing 0 after cleanup is normal. Once kubelet has seen an extended resource type from a device-plugin, it caches the resource name and continues reporting it at 0 even after the device-plugin stops advertising it.

This is standard Kubernetes behavior — these stale entries do not affect scheduling. Kueue and the scheduler simply see zero capacity for those resources, so no pods will be admitted for them. The important thing is that nvidia.com/gpu is back to 4.

5. Restore A100 ClusterQueue to 4 GPUs

$ oc patch clusterqueue a100-cluster-queue --type merge \
  -p '{"spec":{"resourceGroups":[{"coveredResources":["cpu","memory","nvidia.com/gpu"],"flavors":[{"name":"a100-gpu","resources":[{"name":"cpu","nominalQuota":"16"},{"name":"memory","nominalQuota":"64Gi"},{"name":"nvidia.com/gpu","nominalQuota":"4"}]}]}]}}'
clusterqueue.kueue.x-k8s.io/a100-cluster-queue patched

6. Delete MIG Kueue resources

$ oc delete localqueue mig-training-queue -n training-jobs
localqueue.kueue.x-k8s.io "mig-training-queue" deleted from training-jobs namespace

$ oc delete clusterqueue mig-cluster-queue
clusterqueue.kueue.x-k8s.io "mig-cluster-queue" deleted

$ oc delete resourceflavor a100-mig
resourceflavor.kueue.x-k8s.io "a100-mig" deleted
For a complete cluster reset (removing ALL lab resources), see Cluster Reset.
