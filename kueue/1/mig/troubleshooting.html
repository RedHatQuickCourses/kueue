Troubleshooting MIG

If Check MIG resources still shows nvidia.com/gpu: 4 with no MIG resources, work through these checks in order.

1. Is the mig-faker Pod Running?

$ oc get daemonset mig-faker -n gpu-operator

If DESIRED is 0, the mig-faker cannot schedule on your node. The most common cause is a missing toleration — the GPU node has a nvidia.com/gpu=present:NoSchedule taint, but the mig-faker DaemonSet may not tolerate it. Fix with:

$ oc patch daemonset mig-faker -n gpu-operator --type=json \
  -p '[{"op":"add","path":"/spec/template/spec/tolerations","value":[{"key":"nvidia.com/gpu","operator":"Exists","effect":"NoSchedule"}]}]'

After patching, verify the pod starts:

$ oc get daemonset mig-faker -n gpu-operator

DESIRED and READY should both be 1.

2. Did the mig-faker Process the Annotation?

$ oc logs -n gpu-operator -l app=mig-faker --tail=20

  • Success: Look for Successfuly updated MIG config and Labelling node …​ mig.config.state:success

  • Parse error: If you see failed to unmarshal mig config, the annotation format is wrong. The mig-devices field must be an array of objects (- name: …​ position: …​ size: …​), not a map (0: 3g.20gb). See Edit the MIG node configuration for the correct format.

3. Did You Update the Topology ConfigMap?

$ oc get configmap topology-$WORKER_NODE1 -n gpu-operator -o yaml | grep -A 5 otherDevices

If otherDevices is missing, you skipped Update the topology ConfigMap. The device-plugin only knows about resources listed in this ConfigMap.

4. Did You Restart the Device-Plugin?

The device-plugin reads the ConfigMap once at startup. If you updated the ConfigMap but didn’t restart the pod (Restart the device-plugin pod), the device-plugin is still serving the old inventory. Check the device-plugin logs:

$ oc logs -n gpu-operator $(oc get pods -n gpu-operator -l app=device-plugin \
  -o jsonpath="{.items[?(@.spec.nodeName==\"$WORKER_NODE1\")].metadata.name}") --tail=10

You should see lines like Starting device plugin for RealNodeDevicePlugin-nvidia.com/mig-3g.20gb. If you only see RealNodeDevicePlugin-nvidia.com/gpu, the pod is using the old ConfigMap — restart it per Restart the device-plugin pod.
