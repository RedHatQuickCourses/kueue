Update the Topology ConfigMap

The fake GPU operator’s device-plugin reads its GPU inventory from a topology ConfigMap in the gpu-operator namespace — it does not read the run.ai/mig.config annotation from the node. You must manually update this ConfigMap to reflect the MIG partition, then restart the fake GPU operator’s device-plugin pod.

References

  • Fake GPU Operator

Lab: Update Topology and Restart Device-Plugin

1. Update the topology ConfigMap

First, examine the existing ConfigMap to get the GPU UUIDs:

$ oc get configmap topology-$WORKER_NODE1 -n gpu-operator -o yaml
apiVersion: v1
data:
  topology.yml: |
    gpuMemory: 40960
    gpuProduct: NVIDIA-A100-SXM4-40GB
    gpus:
        - id: GPU-9a5be495-3d15-51ae-aaeb-61ebb461dc7e # GPU 0
          status:
...
        - id: GPU-3cd5e88a-e888-5bfb-939a-e93761022345 # GPU 1
          status:
...
        - id: GPU-68b11f81-2618-5b61-b187-4a25afe7205b # GPU 2
          status:
...
        - id: GPU-c9b00e75-53dc-5bec-a55b-842f82213d8a # GPU 3
          status:
...
    migStrategy: mixed
kind: ConfigMap
metadata:
  labels:
    node-name: worker-cluster-vnnbf-1
    node-topology: "true"
  name: topology-worker-cluster-vnnbf-1
  namespace: gpu-operator
...

You will see 4 GPUs listed under gpus:. Note the UUID of the first GPU (GPU 0) — this is the one being MIG-partitioned. You need to remove it and add MIG profiles instead.

Edit kueue-config/6b-mig-topology-update.yaml:

$ vi kueue-config/6b-mig-topology-update.yaml

Replace:

  • metadata.name — set to topology-$WORKER_NODE1

  • labels.node-name — set to $WORKER_NODE1

  • GPU UUIDs — copy the UUIDs for GPUs 1-3 from your existing ConfigMap (leave out GPU 0)

Review kueue-config/6b-mig-topology-update.yaml before applying:

apiVersion: v1
kind: ConfigMap
metadata:
  name: topology-worker-cluster-fn765-1      (1)
  namespace: gpu-operator
  labels:
    node-name: worker-cluster-fn765-1        (1)
    node-topology: "true"
data:
  topology.yml: |
    gpuMemory: 40960
    gpuProduct: NVIDIA-A100-SXM4-40GB
    gpus:                                    (2)
      - id: GPU-1663c532-...
        status: ...
      - id: GPU-747a7a51-...
        status: ...
      - id: GPU-c0edaef3-...
        status: ...
    migStrategy: mixed                       (3)
    otherDevices:                            (4)
      - name: nvidia.com/mig-3g.20gb
        count: 1
      - name: nvidia.com/mig-2g.10gb
        count: 1
      - name: nvidia.com/mig-1g.5gb
        count: 1
1 Both metadata.name and labels.node-name must match your A100 node name (prefixed with topology- for the name).
2 Only 3 GPUs remain in the gpus list — GPU 0 has been removed because it is now MIG-partitioned. Copy the UUIDs for GPUs 1-3 from your existing ConfigMap.
3 migStrategy: mixed tells the device-plugin that this node has both whole GPUs and MIG instances.
4 otherDevices lists the MIG profiles. The fake GPU operator’s device-plugin registers each entry as a separate Kubernetes extended resource (e.g., nvidia.com/mig-3g.20gb).

Apply the updated topology:

$ oc apply -f kueue-config/6b-mig-topology-update.yaml
configmap/topology-worker-cluster-vnnbf-1 configured

This ConfigMap now tells the device-plugin: "this node has 3 whole GPUs plus three MIG devices."

2. Restart the device-plugin pod

The fake GPU operator’s device-plugin reads the topology ConfigMap once at startup. After updating the ConfigMap, you must restart the device-plugin pod on the A100 worker node so it picks up the new inventory:

$ oc delete pod -n gpu-operator $(oc get pods -n gpu-operator -l app=device-plugin \
  -o jsonpath="{.items[?(@.spec.nodeName==\"$WORKER_NODE1\")].metadata.name}")
pod "device-plugin-cpthp" deleted from gpu-operator namespace

Wait about 15 seconds for the new pod to start and register with kubelet. Verify that the device-plugin pods are running.

$ oc get po -n gpu-operator -l app=device-plugin 
NAME                  READY   STATUS    RESTARTS   AGE
device-plugin-s7xxk   1/1     Running   1          29h
device-plugin-t7vbh   1/1     Running   0          35s
