Platform Setup

In this chapter, you install the two foundational components needed before Kueue can manage GPU quotas:

  • Red Hat OpenShift AI (RHOAI) 3.4 and its dependency operators

  • The Fake GPU Operator from Run:ai, which simulates NVIDIA GPUs on CPU-only worker nodes

By the end of this chapter, your cluster will have two worker nodes advertising fake GPUs that behave like real NVIDIA hardware from the Kubernetes scheduler’s perspective.

What Gets Installed

RHOAI 3.4 and Dependencies

A Helm chart installs the RHOAI operator and its dependencies in a single step. The chart also creates a DataScienceCluster CR that activates the platform.

Fake GPU Operator

The Fake GPU Operator deploys a device plugin that advertises nvidia.com/gpu resources to kubelet. Pods can request GPUs and get scheduled normally — without any physical GPU hardware.

What Is Deliberately NOT Installed

  • OpenShift Service Mesh 3 — the OpenShift ingress operator manages this automatically

  • NVIDIA GPU Operator — replaced by the Fake GPU Operator

  • Kueue — installed separately via its own Helm chart (see Install Kueue)

The DataScienceCluster CR sets the kueue component to Unmanaged so that the standalone Kueue operator (installed in the next chapter) can manage it without interference from RHOAI. The codeflare and modelmeshserving components are set to Removed (deprecated).

Why use fake GPUs instead of real hardware?

Real GPU hardware is expensive and scarce in training environments. The Fake GPU Operator lets students learn Kueue’s scheduling, quota management, MIG partitioning, and fair sharing features on any CPU-only OpenShift cluster. The scheduling behavior is identical to real GPUs — pods request nvidia.com/gpu, nodes advertise capacity, and the Kubernetes scheduler places workloads accordingly. The only difference is that no actual GPU computation occurs.
