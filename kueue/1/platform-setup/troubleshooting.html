Troubleshooting and Uninstall

This section covers common issues during RHOAI and Fake GPU Operator installation, and provides uninstall instructions for both components.

Do NOT execute the commands on this page unless you have a failed RHOAI or fake GPU operator installation. If your installation was successful, then move on to the next section on installing Kueue.

Troubleshooting RHOAI

Operator Stuck in "Installing"

Check the install plan and CSV status:

$ oc get installplan -A
$ oc get csv -A | grep -v Succeeded
An InstallPlan stuck in RequiresApproval means the operator subscription has installPlanApproval: Manual. The Helm chart sets automatic approval, but if you modified the subscription, you may need to approve the plan manually.

Subscription Not Creating a CSV

Verify the operator package exists in the catalog:

$ oc get packagemanifest <operator-name> -o jsonpath='{.status.channels[*].name}'
Replace <operator-name> with the actual operator name (e.g., nfd, serverless-operator, authorino-operator, openshift-pipelines-operator-rh, rhods-operator).

DataScienceCluster Not Becoming Ready

Check the RHOAI operator logs:

$ oc logs -n redhat-ods-operator deploy/rhods-operator -f

Check DSC status:

$ oc get datasciencecluster default-dsc -o yaml | grep -A 20 status:

Troubleshooting the Fake GPU Operator

GPU Counts Not Appearing on Nodes

If oc describe node does not show nvidia.com/gpu in the allocatable resources:

  1. Verify the operator pods are running:

    $ oc get pods -n gpu-operator

  2. Verify the node labels are correct:

    $ oc get nodes -l run.ai/simulated-gpu-node-pool

  3. Check the device-plugin pod logs for errors:

    $ oc logs -n gpu-operator -l app=device-plugin
If no device-plugin pods are scheduled, check whether the DaemonSet’s node selector matches your worker node labels. The Fake GPU Operator only deploys device-plugin pods to nodes with the run.ai/simulated-gpu-node-pool label.

Test Pods Stuck in Pending

If test pods remain Pending after applying workloads/pod-gpu-test.yaml:

  1. Check for scheduling errors:

    $ oc describe pod gpu-test-a100

  2. Look for these common causes:

    • Missing toleration — the pod needs nvidia.com/gpu=present:NoSchedule toleration

    • Wrong nodeSelector — the pool name must match the node label exactly

    • Insufficient GPU capacity — all GPUs on the target node are already allocated

Uninstall RHOAI

# Uninstall the Helm release (removes Subscriptions, Namespaces, OperatorGroups, and the DataScienceCluster CR)
$ helm uninstall rhoai-operators

# Clean up CSVs that OLM created
$ oc get csv -A | grep -E 'nfd|serverless|authorino|pipeline|rhods' | awk '{print "oc delete csv " $2 " -n " $1}' | sh
Uninstalling RHOAI removes all operator Subscriptions, the DataScienceCluster CR, and the associated namespaces. Any workbenches, pipelines, or model serving endpoints that depend on RHOAI will stop functioning.

Uninstall the Fake GPU Operator

$ helm uninstall gpu-operator -n gpu-operator
$ oc delete ns gpu-operator

# Remove node labels
$ oc label node $WORKER_NODE1 run.ai/simulated-gpu-node-pool-
$ oc label node $WORKER_NODE2 run.ai/simulated-gpu-node-pool-

# Remove node taints
$ oc adm taint nodes $WORKER_NODE1 nvidia.com/gpu=present:NoSchedule-
$ oc adm taint nodes $WORKER_NODE2 nvidia.com/gpu=present:NoSchedule-
After removing the Fake GPU Operator, nodes will no longer report nvidia.com/gpu in their allocatable resources. Any pods requesting GPU resources will remain Pending until GPUs are re-provisioned.
