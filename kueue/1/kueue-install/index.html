Install the Red Hat Build of Kueue

In this chapter, you install the Red Hat build of Kueue as a standalone operator and configure it for GPU quota management.

The Helm chart installs only the operator — all Kueue resources (ResourceFlavors, ClusterQueues, LocalQueues, WorkloadPriorityClasses) are created manually in the next chapter so you understand how each piece fits together.

Why Kueue Is Installed Separately from RHOAI

RHOAI includes a bundled Kueue component (via the DataScienceCluster), but the RHOAI Helm chart sets it to Unmanaged so RHOAI does not interfere with the standalone operator. Installing Kueue independently lets you:

  • Pin a specific Kueue version

  • Configure the operator separately from the RHOAI lifecycle

  • Understand how Kueue works as a standalone Kubernetes component

The embedded version of Kueue in RHOAI is deprecated. The only supported method is to install the Red Hat build of Kueue operator separately.

What You Will Do

  1. Install the Kueue operator via Helm

  2. Wait for the operator to reach Succeeded

  3. Patch the Kueue CR to disable LocalQueue defaulting and enable BatchJob integration

  4. Verify the Kueue CRDs are registered on the cluster

Kueue vs Kubernetes Scheduler

Kueue does not replace the Kubernetes scheduler. Instead, it acts as an admission controller that decides whether a workload should be allowed to run based on quota, priority, and fair sharing rules. Once Kueue admits a workload, the Kubernetes scheduler handles the actual pod-to-node placement using nodeSelectors, tolerations, and resource requests.

Think of Kueue as the bouncer at the door (who gets in?) and the Kubernetes scheduler as the host inside (where do they sit?).
