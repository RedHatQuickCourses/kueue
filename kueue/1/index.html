GPU Quota Management with Kueue on Red Hat OpenShift AI

Introduction

This hands-on course teaches AI platform engineers how to manage GPU quotas across multiple teams using the Red Hat build of Kueue on Red Hat OpenShift AI clusters with the Fake GPU Operator to simulate NVIDIA GPUs. No physical GPU hardware is required.

Students progress from installing Red Hat build of Kueue on a bare CPU-only OpenShift cluster to configuring multi-team fair sharing, MIG GPU partitioning, priority preemption, and role-based access control.

The course uses the Red Hat build of Kueue and NOT the upstream community version of Kueue. All references to Kueue throughout the course refer to the Red Hat build of Kueue (v1.3).

Course Overview and Objectives

Organizations running GPU workloads on shared OpenShift clusters face a common challenge: how to fairly distribute expensive GPU resources across competing teams while maximizing utilization. This course addresses that challenge using the Red Hat build of Kueue, an open-source Kubernetes-native batch admission system.

Students work through a structured, hands-on lab sequence on a live OpenShift cluster with simulated NVIDIA GPUs:

  • Install and configure the platform: Deploy Red Hat OpenShift AI (RHOAI) 3.4, the Fake GPU Operator that simulates A100 and T4 GPUs on CPU-only nodes, and the Red Hat build of Kueue as a standalone operator

  • Build a GPU quota system from scratch: Create ResourceFlavors, ClusterQueues, LocalQueues, and WorkloadPriorityClasses to enforce organizational GPU quotas

  • Submit and manage GPU workloads: Exercise first-in-first-out (FIFO) admission, priority-based scheduling, and queue isolation with real Kubernetes Jobs and Deployments

  • Enable cross-team GPU sharing: Configure cohort borrowing so that idle GPUs in one team’s queue can be temporarily used by another team, with automatic reclaim when needed

  • Implement fair sharing with preemption: Set up Dominant Resource Share (DRS) fair sharing with configurable weights so teams get proportional access to a shared GPU pool

  • Partition GPUs with MIG: Split an A100 GPU into multiple MIG instances (mixed mode) and configure Kueue to manage both whole and partitioned GPU resources with priority preemption

  • Secure access with RBAC: Apply least-privilege role-based access control using Kueue’s aggregated ClusterRoles to separate platform admin and data scientist permissions

By the end of the course, students will be able to use the Red Hat build of Kueue to maximize GPU utilization, eliminate idle waste, and enforce fair access policies — reducing infrastructure costs while enabling multiple teams to share expensive GPU resources without contention.

Course Duration

Approximately 16 hours total (2 Days)

Target Audience

  • OpenShift administrators responsible for managing shared OpenShift clusters with GPU resources

  • ML engineers and data scientists who submit GPU workloads and need to understand how quota and admission policies affect their jobs

  • AI Platform Engineers designing multi-tenant GPU strategies for AI/ML platforms

Prerequisites

  • Working knowledge of Kubernetes/OpenShift concepts (Pods, Jobs, Deployments, Namespaces, RBAC)

  • Familiarity with the oc or kubectl CLI for cluster administration

  • Basic understanding of Helm for deploying operators

  • No prior experience with Kueue or GPU partitioning (MIG) is required — the course covers these from the ground up

  • Access to a provisioned lab cluster (RHDP or self-managed OpenShift 4.20+ with at least 2 dedicated worker nodes). No real NVIDIA GPUs are needed

Getting Started

Before starting the course, set up your lab environment by following the instructions in Lab Environment. This covers cluster provisioning, hardware requirements, and environment verification.
