Create WorkloadPriorityClasses

WorkloadPriorityClasses control queueing order and preemption within Kueue. Higher values mean higher priority.

Concepts

WorkloadPriorityClasses are different from Kubernetes PriorityClasses — they only affect Kueue’s admission decisions, not the kubelet scheduler.

When a ClusterQueue is full:

  1. Pending workloads are ordered by their WorkloadPriorityClass value (highest first)

  2. If the ClusterQueue’s preemption policy allows it (withinClusterQueue: LowerPriority), a high-priority workload can evict a running low-priority one to free capacity

  3. The evicted workload returns to the pending queue and waits for capacity

References

  • Kueue: WorkloadPriorityClass

  • Kubernetes: Pod Priority and Preemption (for comparison)

Lab: Create WorkloadPriorityClasses

1. Create WorkloadPriorityClasses

  1. Review kueue-config/5-workload-priority-classes.yaml before applying:

    apiVersion: kueue.x-k8s.io/v1beta2
kind: WorkloadPriorityClass
metadata:
  name: low-priority          (1)
value: 100                    (2)
description: "Low priority — batch training jobs that can wait or be preempted"  (3)
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: WorkloadPriorityClass
metadata:
  name: medium-priority
value: 500
description: "Medium priority — standard training and inference workloads"
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: WorkloadPriorityClass
metadata:
  name: high-priority
value: 1000
description: "High priority — critical inference services and urgent training jobs"
    1 The name is what workloads reference in the spec.priorityClassName field of their pod template.
    2 The value is a numeric priority — higher numbers mean higher priority. When the ClusterQueue is full, Kueue admits higher-value workloads first and can preempt lower-value ones.
    3 The description is informational only — it helps administrators and users understand the intended use case for each priority level.

    When the ClusterQueue is full, a high-priority (1000) workload can preempt a low-priority (100) one because we set withinClusterQueue: LowerPriority on the ClusterQueues in the previous section.

  2. Apply the configuration:

    $ oc apply -f kueue-config/5-workload-priority-classes.yaml
workloadpriorityclass.kueue.x-k8s.io/low-priority created
workloadpriorityclass.kueue.x-k8s.io/medium-priority created
workloadpriorityclass.kueue.x-k8s.io/high-priority created

  3. Verify:

    $ oc get workloadpriorityclasses
NAME              VALUE
high-priority     1000
low-priority      100
medium-priority   500
You will use these priority classes in the Priority-Based Admission exercise to see how Kueue orders and preempts workloads based on priority.
WorkloadPriorityClass vs Kubernetes PriorityClass

Kubernetes has its own PriorityClass resource that controls kubelet scheduler preemption. Kueue’s WorkloadPriorityClass is a separate concept:

  • Kubernetes PriorityClass affects pod scheduling — the kubelet scheduler uses it to decide which pods to evict when a node is overcommitted

  • Kueue WorkloadPriorityClass affects queue admission — Kueue uses it to decide which workloads to admit first and which to preempt when quota is exhausted

In this course, you only use Kueue WorkloadPriorityClasses. The Kubernetes PriorityClass is not needed because Kueue manages admission before pods are ever created.
