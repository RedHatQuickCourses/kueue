Lab: Verify Configuration

1. Verify the full Kueue configuration

Check that everything is wired up correctly:

  1. List all ResourceFlavors:

    $ oc get resourceflavors

  2. Describe both ClusterQueues:

    $ oc describe clusterqueue a100-cluster-queue
$ oc describe clusterqueue t4-cluster-queue

  3. List all LocalQueues — verify they reference the correct ClusterQueues:

    $ oc get localqueues -A

  4. List all WorkloadPriorityClasses:

    $ oc get workloadpriorityclasses

Summary

You have created a complete Kueue GPU quota management configuration:

File Resources Scope

1-namespaces.yaml

training-jobs, inference-apps namespaces + SCC RoleBindings

Namespace

2-resource-flavors.yaml

a100-gpu, t4-gpu flavors with node labels and tolerations

Cluster

3-cluster-queues.yaml

a100-cluster-queue (4 GPUs), t4-cluster-queue (2 GPUs)

Cluster

4-local-queues.yaml

training-queue → A100, inference-queue → T4

Namespace

5-workload-priority-classes.yaml

low-priority (100), medium-priority (500), high-priority (1000)

Cluster

The resource chain is now complete:

  1. Workloads submit to a LocalQueue in their namespace

  2. The LocalQueue forwards to a ClusterQueue for admission

  3. The ClusterQueue checks quotas and priority to decide whether to admit

  4. Admitted workloads inherit nodeLabels and tolerations from the ResourceFlavor

  5. The Kubernetes scheduler places pods on the matching GPU nodes

In the next chapter, you submit workloads to test FIFO admission, priority-based admission, and cross-queue isolation.
