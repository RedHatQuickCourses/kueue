== Lab: Verify Configuration

=== 1. Verify the full Kueue configuration

Check that everything is wired up correctly:

a. List all ResourceFlavors:
+
[source,console,subs="+quotes"]
----
$ **oc get resourceflavors**
----

b. Describe both ClusterQueues:
+
[source,console,subs="+quotes"]
----
$ **oc describe clusterqueue a100-cluster-queue**
$ **oc describe clusterqueue t4-cluster-queue**
----

c. List all LocalQueues -- verify they reference the correct ClusterQueues:
+
[source,console,subs="+quotes"]
----
$ **oc get localqueues -A**
----

d. List all WorkloadPriorityClasses:
+
[source,console,subs="+quotes"]
----
$ **oc get workloadpriorityclasses**
----

== Summary

You have created a complete Kueue GPU quota management configuration:

[cols="2,3,1", options="header"]
|===
|File |Resources |Scope

|`1-namespaces.yaml`
|`training-jobs`, `inference-apps` namespaces + SCC RoleBindings
|Namespace

|`2-resource-flavors.yaml`
|`a100-gpu`, `t4-gpu` flavors with node labels and tolerations
|Cluster

|`3-cluster-queues.yaml`
|`a100-cluster-queue` (4 GPUs), `t4-cluster-queue` (2 GPUs)
|Cluster

|`4-local-queues.yaml`
|`training-queue` -> A100, `inference-queue` -> T4
|Namespace

|`5-workload-priority-classes.yaml`
|`low-priority` (100), `medium-priority` (500), `high-priority` (1000)
|Cluster
|===

The resource chain is now complete:

. Workloads submit to a *LocalQueue* in their namespace
. The LocalQueue forwards to a *ClusterQueue* for admission
. The ClusterQueue checks *quotas* and *priority* to decide whether to admit
. Admitted workloads inherit *nodeLabels* and *tolerations* from the *ResourceFlavor*
. The Kubernetes scheduler places pods on the matching GPU nodes

In the xref:gpu-workloads:index.adoc[next chapter], you submit workloads to test FIFO admission, priority-based admission, and cross-queue isolation.
