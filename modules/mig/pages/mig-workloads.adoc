= Submit MIG Workloads
:navtitle: MIG Workloads

With the MIG Kueue resources in place, you submit three Jobs -- one targeting each MIG profile -- and verify that Kueue admits them to the correct MIG slots.

== References

* https://kueue.sigs.k8s.io/docs/concepts/workload/[Kueue: Workload^]
* https://docs.nvidia.com/datacenter/tesla/mig-user-guide/[NVIDIA: Multi-Instance GPU User Guide^]
* https://docs.redhat.com/en/documentation/openshift_container_platform/4.20/html-single/ai_workloads/index#managing-workloads[Red Hat build of Kueue: Managing Jobs and Workloads^]

== Lab: Submit Jobs to MIG Profiles

=== 1. Submit MIG workloads

Submit three Jobs, one targeting each MIG profile.
Each Job requests a specific MIG resource type instead of `nvidia.com/gpu`.

a. Review `workloads/job-mig.yaml` before applying.
The file contains three Jobs; here is one representative Job (the other two follow the same pattern with different MIG profiles):
+
[source,yaml]
----
apiVersion: batch/v1
kind: Job
metadata:
  name: mig-job-3g-20gb                                # <1>
  namespace: training-jobs
  labels:
    kueue.x-k8s.io/queue-name: mig-training-queue      # <2>
spec:
  suspend: true                                        # <3>
  template:
    metadata:
      annotations:
        run.ai/simulated-gpu-utilization: "70-90"
    spec:
      restartPolicy: Never
      containers:
      - name: mig-workload
        image: registry.access.redhat.com/ubi9/ubi
        command: ["/bin/bash", "-c"]
        args: [...]
        resources:
          requests:
            cpu: "2"
            memory: "8Gi"
            nvidia.com/mig-3g.20gb: "1"                # <4>
          limits:
            nvidia.com/mig-3g.20gb: "1"                # <5>
----
<1> Each Job name includes the MIG profile it targets for easy identification.
<2> Submits to `mig-training-queue`, which is backed by `mig-cluster-queue` with the `a100-mig` flavor.
<3> `suspend: true` is required for Kueue-managed Jobs. Kueue unsuspends the Job when it is admitted.
<4> Instead of `nvidia.com/gpu`, the Job requests a specific MIG resource type. Kueue matches this against the MIG quotas in `mig-cluster-queue`.
<5> Limits must match requests for GPU/MIG resources -- Kubernetes requires this for extended resources.

b. Apply the Jobs:
+
[source,console,subs="+quotes"]
----
$ **oc apply -f workloads/job-mig.yaml**
job.batch/mig-job-3g-20gb created
job.batch/mig-job-2g-10gb created
job.batch/mig-job-1g-5gb created
----
+
This creates:
+
[cols="2,2,1,1,1", options="header"]
|===
|Job |MIG Resource |Compute |Memory |CPU/Mem

|`mig-job-3g-20gb`
|`nvidia.com/mig-3g.20gb: 1`
|3 slices
|20 GiB
|2 CPU, 8Gi

|`mig-job-2g-10gb`
|`nvidia.com/mig-2g.10gb: 1`
|2 slices
|10 GiB
|2 CPU, 4Gi

|`mig-job-1g-5gb`
|`nvidia.com/mig-1g.5gb: 1`
|1 slice
|5 GiB
|1 CPU, 2Gi
|===
+
All three submit to `mig-training-queue` and should be admitted immediately since each MIG profile has exactly 1 instance available.

c. Verify the Jobs are admitted and running.
+
Check that all three Kueue workloads are admitted:
+
[source,console,subs="+quotes"]
----
$ **oc get workloads -n training-jobs**

job-mig-job-3g-20gb-87347   mig-training-queue   mig-cluster-queue   True                  27s
----
+
Check that pods are running on the A100 node:

[source,console,subs="+quotes"]

+
.How to verify each Job runs on its MIG instance
****
. *Kueue admission* -- `oc get workloads` shows all three admitted via `mig-cluster-queue`
. *Node placement* -- `oc get pods -o wide` shows all pods on the A100 node (worker-1)
. *Resource consumption* -- `oc describe clusterqueue mig-cluster-queue` shows each MIG profile's usage at 1/1
. *Pod resource requests* -- each pod's resource request shows its specific MIG type (not `nvidia.com/gpu`)
****
+
[NOTE]
====
The fake `nvidia-smi` in MIG jobs will show `0MiB` memory usage even though the pods have `run.ai/simulated-gpu-utilization` annotations.
This is a known limitation of the fake GPU operator -- its status-updater only tracks allocation for pods requesting `nvidia.com/gpu` (whole GPUs), not `nvidia.com/mig-*` resources.

The `nvidia-smi` output still correctly shows the A100 GPU product name, confirming the pod is on the right node, but simulated GPU utilization is not supported for MIG workloads.

On real hardware with the NVIDIA GPU Operator, `nvidia-smi` would show individual MIG instances with their memory usage.
For this lab, use the four verification methods above (Kueue admission, node placement, ClusterQueue usage, and pod resource requests) instead of nvidia-smi to confirm MIG is working.
====

d. Clean up the MIG Jobs:
+
[source,console,subs="+quotes"]
----
$ **oc delete jobs -n training-jobs mig-job-3g-20gb mig-job-2g-10gb mig-job-1g-5gb**
job.batch "mig-job-3g-20gb" deleted from training-jobs namespace
job.batch "mig-job-2g-10gb" deleted from training-jobs namespace
job.batch "mig-job-1g-5gb" deleted from training-jobs namespace
----
