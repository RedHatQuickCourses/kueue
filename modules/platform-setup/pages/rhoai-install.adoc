= Install RHOAI 3.4 and Dependencies
:navtitle: Install RHOAI

Red Hat OpenShift AI (RHOAI) is the AI/ML platform built on OpenShift.
In this section, you install RHOAI 3.4 and its dependency operators using a single Helm chart, then verify the deployment.

== Concepts

The Helm chart creates OLM Subscriptions for each operator.
OLM installs the operators asynchronously -- each operator downloads its container images and transitions through `Installing` to `Succeeded` independently.

After all operators are ready, you apply a DataScienceCluster (DSC) custom resource separately.
The DSC activates the RHOAI platform components.
Some components are set to `Managed` (active), while others like `kueue` are set to `Unmanaged` to avoid conflicts with the standalone Kueue operator installed later.

NOTE: The DSC is applied as a separate step because its CRD is only registered after the RHOAI operator finishes installing.
Attempting to create the DSC before the operator is ready results in a "no matches for kind DataScienceCluster" error.

== Lab: Install RHOAI

=== 1. Review and edit values.yaml

Review the Helm chart values and adjust if needed:

[source,console,subs="+quotes"]
----
$ **cat helm-charts/rhoai-3.4/values.yaml**
----

The defaults install all RHOAI 3.4 dependency operators.
If any operator is already installed on your cluster, set its `enabled` field to `false` in `values.yaml`.

TIP: Before installing, check which operators are already on your cluster with `oc get csv -A`.
If you see an operator listed in the table above already at `Succeeded`, disable it in the values file to avoid conflicts.

=== 2. Install RHOAI 3.4 and dependencies

a. Run the Helm install:
+
[source,console,subs="+quotes"]
----
$ **helm install rhoai-operators ./helm-charts/rhoai-3.4**

NAME: rhoai-operators
LAST DEPLOYED: Mon Jun  8 10:05:38 2026
NAMESPACE: default
STATUS: deployed
REVISION: 1
DESCRIPTION: Install complete
...
----
+
This creates all operator Subscriptions.
OLM will install each operator asynchronously.

b. Monitor operator installation progress:
+
[source,console,subs="+quotes"]
----
$ **watch "oc get csv -A | grep -E 'nfd|serverless|authorino|pipeline|rhods'"**
----
+
Wait until every operator shows *Succeeded* in the PHASE column.
This typically takes 5-10 minutes.

c. Check subscriptions:
+
[source,console,subs="+quotes"]
----
$ **oc get sub -A | grep -E 'nfd|serverless|authorino|pipeline|rhods' **

openshift-nfd           nfd                                nfd                                 redhat-operators   stable
openshift-operators     authorino-operator                 authorino-operator                  redhat-operators   stable
openshift-operators     openshift-pipelines-operator-rh    openshift-pipelines-operator-rh     redhat-operators   latest
openshift-serverless    serverless-operator                serverless-operator                 redhat-operators   stable
redhat-ods-operator     rhods-operator                     rhods-operator                      redhat-operators   stable-3.4
----

IMPORTANT: Do not proceed to the next step until all operators show `Succeeded`.
An operator stuck in `Installing` will cause downstream failures when the DataScienceCluster tries to activate its components.

=== 3. Create the DataScienceCluster

Once all operators show `Succeeded`, apply the DataScienceCluster CR:

[source,console,subs="+quotes"]
----
$ **oc apply -f helm-charts/rhoai-3.4/dsc.yaml**
datasciencecluster.datasciencecluster.opendatahub.io/default-dsc created
----

This activates the RHOAI platform components.
Note that `kueue` is set to `Unmanaged`. This settings tells RHOAI not to install its own embedded version of Kueue, because you install the standalone Red Hat build of Kueue in the next chapter.

=== 4. Verify RHOAI deployment

a. Verify the DataScienceCluster:
+
[source,console,subs="+quotes"]
----
$ **oc get datasciencecluster default-dsc**
NAME          READY   REASON
default-dsc   False   NotReady
----
+
NOTE: The DSC will show `Ready: False` until you install the standalone Kueue operator in the next chapter.
This is expected and does not affect the other RHOAI components.

b. Check the RHOAI dashboard route:
+
[source,console,subs="+quotes"]
----
$ **oc get route -n redhat-ods-applications**
NAME                   HOST/PORT     ...
data-science-gateway   data-science-gateway...
rhods-dashboard        rhods-dashboard-redhat-ods-applications...
----
+
Open the URL in your browser to verify the RHOAI dashboard is accessible.

c. To inspect or modify DSC components later (e.g., enable/disable a component):
+
[source,console,subs="+quotes"]
----
$ **oc edit datasciencecluster default-dsc**
----

== Customization Options

You do not need to make any of these changes for this course.
They are documented here for reference if you need to adapt the installation to a different cluster configuration.

=== Skip an Already-Installed Operator

Edit `helm-charts/rhoai-3.4/values.yaml` and set `enabled: false` for any operator already on your cluster:

[source,yaml]
----
pipelines:
  enabled: false   # Already installed
----

=== Change Operator Channel/Version

Edit `helm-charts/rhoai-3.4/values.yaml` to pin a specific channel:

[source,yaml]
----
serverless:
  channel: stable-1.34   # Pin a specific Serverless version
----

=== Change DSC Component State

Edit `helm-charts/rhoai-3.4/dsc.yaml` to change component states before applying.
For example, to disable TrustyAI:

[source,yaml]
----
    trustyai:
      managementState: Removed
----

=== Override Operator Values via Command Line

You can also override Helm values without editing the file:

[source,console,subs="+quotes"]
----
$ **helm install rhoai-operators ./helm-charts/rhoai-3.4 --set pipelines.enabled=false**
----

.How OLM Manages Operator Lifecycle
[sidebar]
****
The Operator Lifecycle Manager (OLM) watches for Subscription resources and automatically installs the requested operator version.
Each operator goes through several phases: `Pending` -> `InstallReady` -> `Installing` -> `Succeeded`.
The Helm chart creates Subscriptions, but OLM does the actual installation -- downloading images, creating Deployments, and registering CRDs.

If an operator gets stuck, check the InstallPlan (`oc get installplan -A`) and the CSV status (`oc get csv -A | grep -v Succeeded`) for error details.
****
