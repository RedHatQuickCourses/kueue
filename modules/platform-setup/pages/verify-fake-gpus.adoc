= Verify Fake GPUs
:navtitle: Verify Fake GPUs

With the Fake GPU Operator installed, you now verify that the simulated GPUs appear as allocatable resources on the worker nodes.
Then you deploy test pods that run `nvidia-smi` to confirm the simulated GPU hardware is visible inside containers.

== References

* https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/#extended-resources[Kubernetes: Extended Resources^]
* https://docs.nvidia.com/deploy/nvidia-smi/index.html[NVIDIA: nvidia-smi Documentation^]
* https://kubernetes.io/docs/tasks/configure-pod-container/assign-pods-nodes/#create-a-pod-that-gets-scheduled-to-your-chosen-node[Kubernetes: Assign Pods to Nodes with nodeSelector^]

=== 2. Deploy test pods with nvidia-smi

a. Deploy two pods that each request a GPU -- one targeting the A100 node, one targeting the T4 node:
+
[source,console,subs="+quotes"]
----
$ **oc apply -f workloads/pod-gpu-test.yaml**
pod/gpu-test-a100 created
pod/gpu-test-t4 created
----
+
This creates:
+
[cols="1,2,2,2", options="header"]
|===
|Pod |Node Pool |Fake GPU |Simulated Utilization

|`gpu-test-a100`
|`a100-pool` (worker-1)
|1x A100 (40 GiB)
|60-90% (training pattern)

|`gpu-test-t4`
|`t4-pool` (worker-2)
|1x T4 (16 GiB)
|10-30% (inference pattern)
|===
+
Each pod has two scheduling controls:
+
* *`nodeSelector`* -- targets the specific GPU pool (A100 or T4)
* *`tolerations`* -- allows the pod to run on tainted GPU nodes
+
WARNING: Without the toleration, the pod stays Pending even though it requests `nvidia.com/gpu`.
This mirrors real-world GPU clusters where only GPU workloads are permitted on GPU nodes.
+
The utilization annotations simulate different workload patterns -- heavy usage (60-90%) for training on the A100, light usage (10-30%) for inference on the T4.

b. Verify each pod landed on the correct node:
+
[source,console,subs="+quotes"]
----
$ **oc get pods gpu-test-a100 gpu-test-t4 -o wide**

== Summary

You have verified that:

* Worker-1 reports *4x nvidia.com/gpu* (A100 pool)
* Worker-2 reports *2x nvidia.com/gpu* (T4 pool)
* Test pods land on the correct nodes based on `nodeSelector`
* `nvidia-smi` inside containers shows the correct GPU model and memory
* Taints and tolerations correctly control pod placement

.How the Fake GPU Operator Simulates nvidia-smi
[sidebar]
****
The operator's device-plugin DaemonSet mounts a fake `nvidia-smi` binary into each GPU container.
This binary reads the GPU topology from a ConfigMap in the `gpu-operator` namespace and returns output that matches the configured GPU model, memory size, and simulated utilization.

The status-updater component periodically updates the simulated utilization values based on annotations on each pod (`run.ai/simulated-gpu-utilization`).
This is why different pods show different utilization percentages -- each pod's annotation controls what `nvidia-smi` reports.
****
